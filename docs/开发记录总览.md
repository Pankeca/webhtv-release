### 2.2 关键决策

| 决策 | 结论 | 依据 |
|---|---|---|
| 触屏优化 | 不做 | tangtv 的 `isTouchOptimized()` 有 `Util.isLeanback()` 硬门禁，手机版空转 |
| 搜索线程设置 | 不做 | 我方 `Task.largeExecutor()` 固定 20 线程，收益极小 |
| TMDB | 不做 | `TmdbDetailActivity` 13,268 行，迁移成本远大于收益 |
| 音频/语音识别去广 | 不做 | 默认关闭、仅 Exo 点播、需联网下 ASR 模型、APK +16 MB/ABI、关键词覆盖面窄 |
| 换 tangtv 基座 | 不做 | GPL-3.0 传染；基座从 5.6.4 退回 5.6.0；核心文件重写导致我方改动需二次落地 |
| 构建范围 | 只打 mobile arm64 | 用户明确要求，减少构建时间与产物维护成本 |
| 扩展存储方式 | 存链接不存内容 | `WebHomeExtensionRegistry.loadRemote()` 以链接为 base 解析相对 `js` 路径 |

## 4. 踩坑合辑

### 4.1 构建环境

1. 宿主 `ulimit -v` 锁 4 GB，Gradle 起不来，必须用容器 `hostroot:1`。
2. 容器挂载**必须**含 `/usr/lib/locale:ro`，否则 assets 中文文件名导致 `mergeAssets` 报 `Invalid file path`；含 `/home/s/.android:/root/.android`，否则容器自建 debug keystore，装不上真机。
3. 容器内 `/tmp` 不存在，需 `mkdir -p /tmp && chmod 1777 /tmp`，否则 `java.io.tmpdir` 报不存在。
4. Chaquopy 要求 Python 3.10（`/home/s/.local/bin/python3.10`），需挂 `/home/s/.local` 并加入 PATH。
5. `armeabi-v7a` 首次构建会从 PyPI 拉依赖，实测约 8 KB/s 超时；把 `PIP_INDEX_URL` 指向清华镜像即可。
6. 外置盘是 FUSE/NTFS，Gradle 锁/文件哈希容易报权限错误；构建副本放 ext4 的 `/home/s/REA-src`，并加 `--no-daemon`。
7. 冷编译首次约 28 分钟；全量单测约 11 分钟，按需 `--tests` 过滤。

### 4.2 签名

1. Release 包未配置签名会静默退化为 debug 签名，必须 `apksigner verify` 确认 `CN=WebHTV`。
2. debug 与 release 签名不一致，装发布包前必须先卸载旧包（会清数据）。
3. `/home/s/REA-src/local.properties` 含 4 行 debug 签名配置，**不要提交、不要被整树同步覆盖**。
4. 迁移到 REA 时，`secrets/webhtv-release.env` 的 `WEBHTV_STORE_FILE` 仍指向原机路径，换机要手动改；外置盘 777 挂载使 0600 无效，密钥只作本机迁移用。

### 4.3 Git / GitHub / CNB

1. REA 与 GitHub 远端**无共同祖先**，不能用常规 push；用 `bash /home/s/pub/replay-head.sh "提交说明"`（blobless + read-tree/write-tree/commit-tree），**禁止 force push**。
2. 网络不对称：上传约 5 MB/s，下载约 20 KB/s，全量 clone 336 MB 工作树不可行。
3. CNB push 必须写 `git -c credential.helper='!cnb git-credential' push origin HEAD:main`，感叹号不能少。
4. `.gitignore` 必须排除 `*.apk` / `*.aab` / `secrets/`，单个 APK 约 140~150 MB。
5. `app/libs`、`third_party/**/prebuilt` 的 `.so/.a`/.aar 是 vendored 产物，**故意入库**，删了编不出包。

### 4.4 Android UI / 布局

1. `smallestScreenWidthDp` 优先于 orientation：`layout-sw600dp` 会覆盖 `layout-land`，平板横竖屏共用 land 布局是预期行为。
2. manifest 声明 `configChanges` 后旋转不重建；手机横竖屏资源布局不同时必须主动 `recreate()`。
3. `FixedNestedScrollView` 原为电视遥控器写的（`onInterceptTouchEvent` 返回 false、`scrollTo` 强制 y=0、`fling` 置空），手机上完全滚不动；手机端必须用标准 `NestedScrollView`。
4. Flexbox `NOWRAP` 下默认 `flexShrink=1` 会把站点胶囊压成竖排文字；每个胶囊要 `setFlexShrink(0)` + `WRAP_CONTENT`。
5. `menu_vod` 用 `always` 会挤掉标题和账号图标，改 `ifRoom`；小屏顶栏按钮常驻需另做布局。
6. 详情页 `episode` 的 `maxHeight`（竖屏 280dp / 横屏 328dp）会限制集数空间，已移除；选集自动定位不能再滚 `RecyclerView` 自身，要滚外层页面。
7. 标签容器从 `GONE` 改 `INVISIBLE`，避免高度塌陷压到海报顶部。
8. `DownloadCenterActivity` 未导出，`adb shell am start` 会被 `SecurityException` 拒绝，只能走 UI 或通知栏入口。
9. 详情页小屏弹窗高度按屏高动态计算（竖屏 66% / 横屏 54%），不要写死。

### 4.5 触摸 / 滚动 / 播放

1. `CustomRecyclerView` 在 `ACTION_DOWN` 就禁止父级拦截，会导致整页无法滚动；改为按手势主方向（纵向交给外层、横向自己消费）。
2. 旋转重建后新 `PlayerView` 未绑 `Player` → 只有声音/黑屏/转圈，必须 `setRender()`。
3. 旋转后选集丢失的根因是重建触发二次请求；用静态缓存 `Vod` + key，重建后本地 `setDetail`。
4. 选中集数自动滚动时，页面还在顶部不要抢滚动，避免刚进详情页就跳离视频和站点栏。

### 4.6 弹幕 / 去广

1. 扩展存内容不存链接会解析失败（manifest 全是相对路径）。
2. `contains(".js")` 判断脚本会把 `.manifest.json` 误判为脚本，必须后缀精确匹配并剥离 query/fragment。
3. 弹幕「测速能过、播放没弹幕」需要匹配端与获取端同时放宽。
4. 去广规则必须有比例/时长安全上限（35% / 90 秒），内置规则默认关闭，避免误删正片。

### 4.7 ADB / 真机验证

1. WebView 源的网页播放器不接管，最可靠入口是本地 server 推送：
   ```bash
   adb forward tcp:19978 tcp:9978
   curl "http://127.0.0.1:19978/action?do=push&url=<urlencoded>"
   ```
   推裸片名（如「庆余年」）会触发智能匹配，直接进正式播放页。
2. 全屏 `input tap` 会先落到视频层且控件约 3 秒自动隐藏：先点 `958 597` 点亮控件，0.3~0.4 秒内再点目标。
3. `input text` 不支持中文；关键词靠推送标题携带，用 DPAD_LEFT/RIGHT + DEL 修剪。
4. 截图实际 1920×1200（工具显示 1080×675），坐标按 1.778 换算；底栏按钮 y≈1161~1163，y≥1178 会被手势区吞掉。
5. 平板可用 `wm size 1080x1920` + `wm density 480` 模拟 360×640dp 手机屏，验证后 `wm size reset` / `wm density reset`。

### 4.8 服务端 / 发布

1. EdgeOne Pages 默认域名（`*.edgeone.dev` / `*.edgeone.cool`）有登录墙，必须绑自定义域名；海外区才能添加自定义域名。
2. EdgeOne 新项目偶发 `teo.CreatePagesResources`，平台瞬时故障重试即可。
3. 上游 `node-functions/[[...path]]..js` 文件名有误，要改成 `[[...path]].js`；`edgeone.json` 的 rewrites 校验不通过要删。
4. CNB raw 直链硬限制 100 MiB，超出返回 413（与网络无关，Range 同样 413），必须走仓库 zip 归档。
5. 发布清单的 `apk` 要换成 CNB 地址或带加速线路兜底，GitHub Release 在部分网络下 130 MB+ 会 timeout。

### 5.2 修改代码前必须知道

1. **只改 REA**，再只拷改动文件到 `/home/s/REA-src`；整树 rsync 会覆盖 `local.properties` 的调试签名配置。
2. 布局改动先确认四套 `activity_video.xml` 是否需要同步；文案改动三语 `strings.xml` 一起改。
3. mobile 专属类（下载中心、个人中心、`EpisodeChipConfig` 等）不要移到 `main`，会让 leanback 编译失败。
4. 涉及旋转 / 播放的改动，必须真机验证「播放中双向旋转，画面与进度连续、选集与站点栏保留」。
5. 涉及 `Setting` 新 prefs 的改动，要登记到 `Backup.APP_PREFS`，否则云备份/恢复会丢配置。
6. 涉及更新/清单的改动，要同时验证 GitHub 直链、加速线路、CNB 归档三条路径。
7. 单测优先覆盖纯逻辑（URL 分类、m3u8 解析、规则匹配、弹幕解析），不要依赖 Android 框架类。

### 5.3 明确不做（避免重复讨论）

音频/语音识别去广、触屏优化、搜索线程设置、TMDB、换 tangtv 基座。理由见第 2.2 节与 `tangtv-rebase-evaluation.md`。
